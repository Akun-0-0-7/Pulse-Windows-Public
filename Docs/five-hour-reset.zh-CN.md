# 五小时额度重置后发送一次 hi

本文保留 0.1.5 的历史行为说明。0.1.6 已加入满额检测、失败恢复和手动重试，请使用[当前版本的发送与恢复说明](window-starter-recovery.zh-CN.md)。

Pulse Windows 0.1.5 可在服务商报告的五小时额度重置时间到达后，通过本机 Codex 或 Claude Code 工具发送一次 `hi`，随后请求刷新额度。`hi` 是普通消息，会使用账号额度；重置时间和额度仍以服务商返回的数据为准。

## 开启条件

此选项默认关闭。先安装并登录本机工具，再在 Pulse 启用对应主账号，并勾选“5 小时重置后发送一次 hi 并刷新额度”。

Codex 在 Pulse 保存了登录时，程序会核对它与本机工具是否为同一账号；身份不一致或无法核实时不发送。自定义 `CODEX_HOME`（Codex 数据目录）时，也按工具实际使用的目录核对。API 密钥是供程序访问服务接口的凭据，不用于本功能。额外账号不借用本机主账号发送消息；Claude 的独立凭据账号也不使用本机启动器。

## 执行时间

“网络与刷新”中的允许开始和结束时间决定执行时段。两者都设为 `00` 表示全天执行；开始与结束相同也表示全天。

程序运行且电脑处于唤醒状态时，每秒检查一次已记录的五小时计划。这项检查独立于普通额度刷新间隔。程序退出或电脑睡眠期间不会执行。

0.1.5 使用服务商返回的五小时窗口倒计时，不按“剩余 100%”直接触发。手动提前重置后，即使读数恢复满额，也不会仅凭该满额读数立即发送。每周、按模型分组和估算窗口不另行触发。

新的有效读数会更新尚未到点的未来计划。程序首次读到一个已经过去的时间，不会单凭该读数补发；事先保存的计划可以在到期后五分钟内补处理，超过五分钟则跳过。

## 发送与刷新

到点后先保存本轮认领记录，再调用本机工具发送。重启后同一周期不会重复；发送失败、超时或中断，也不会循环重发。保存认领记录失败时不发送；历史记录损坏或不可读时暂停自动发送。

发送开始时请求一次额度刷新，发送结束后再请求一次。界面保持服务商实际读数，不因已经发送 `hi` 就人工增加百分比或填写新的重置时间。

Codex 正常退出并返回有效的请求完成事件及输出计数，才记为成功。短消息的用量可能不足以改变界面显示的整数百分比；“已发送”状态依据请求完成确认。Token 是模型处理文本的计数单位。

点击“刷新额度”只查询额度；重新勾选开关也不会补发已认领周期的消息。失败排查见[发送失败说明](reset-send-hotfix.zh-CN.md)。

## 执行记录

数据位于 `%LOCALAPPDATA%\PulseWindows`；`%LOCALAPPDATA%` 表示当前 Windows 用户的本机应用数据目录。

| 文件 | 含义 |
|---|---|
| `window-starter-state.json` | 未来重置计划和已认领周期，用于重启去重。 |
| `window-starter-last.json` | 最近一次处理的状态、时间、完成标记、退出码及计数，不含登录凭据。 |
| `window-starter/` | 本机工具的独立工作目录。 |

JSON 是带字段名称的数据文本格式。排查时保留这些记录，先查看失败类别；删除状态文件会失去本轮去重依据。
