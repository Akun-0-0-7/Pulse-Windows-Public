# 0.1.5 自动发送与故障排查

本文记录 0.1.5 的历史行为。0.1.6 的自动补发、手动重试及执行状态见[当前版本的发送与恢复说明](window-starter-recovery.zh-CN.md)。

0.1.5 修复了自动发送 `hi` 时的系统代理传递，并增加 Codex 请求完成确认。额度查询和消息发送使用不同路径：能看到额度，不代表本机工具已成功发送消息。

## 本版处理方式

- 本机工具沿用 Pulse 的系统代理、自定义代理或直连选择。HTTP 与 HTTPS 是服务请求使用的两种网络协议；系统代理会分别解析并传给本机工具。
- Codex 使用独立配置和临时会话发送普通 `hi`，保留本机登录。该请求会使用账号额度。
- 只有正常退出、未超时、收到有效完成事件和正数输出计数，才记为成功。
- 最新有效读数替换尚未到点的未来计划。启动及打开设置时，会补读陈旧或失败的额度数据。
- 同一周期发送前先保存认领记录；失败后不循环补发。

本版仍按五小时重置时间倒计时触发，详细规则见[五小时自动发送说明](five-hour-reset.zh-CN.md)。

## 按状态检查

| 账号页状态 | 含义与处理 |
|---|---|
| 未找到本机工具 | 检查本机是否安装相应工具，以及账号页“本机工具完整路径”是否正确。 |
| 登录已失效 | 在本机工具重新登录，再确认 Pulse 监控的是同一账号。 |
| 网络连接失败或发送超时 | 检查 Windows、Pulse 和代理软件的代理选择，确认本机工具能够正常连接服务。 |
| Codex 未确认请求完成 | 本轮未取得有效完成回执，不能记为成功；保留执行记录排查。 |
| 无法保存执行记录 | 检查个人数据目录的写入权限。此次不会发送消息。 |
| 无法读取执行记录 | 自动发送暂停；先保留故障文件，检查文件及读取权限。 |
| 发送失败 | 概括性失败，需要结合该机执行记录和本机工具版本定位。 |
| 已发送 hi 并请求刷新额度 | 已收到发送完成确认，并请求查询额度；界面显示的重置时间仍以服务商最新读数为准。 |

本机工具版本不同可能支持不同参数。报告问题时附上工具版本有助于判断；无需为排查反复发送测试消息。

## 提供执行记录

在出现问题的电脑上按 Windows 键和 R 键，输入：

```text
%LOCALAPPDATA%\PulseWindows
```

`%LOCALAPPDATA%` 表示当前 Windows 用户的本机应用数据目录。找到 `window-starter-last.json`，用记事本打开并提供对应账号记录，同时说明 Pulse 版本、Windows 版本和账号页提示。该文件不保存登录凭据、消息完整输出或工具完整错误输出。

JSON 是带字段名称的数据文本格式。常用字段如下：

| 字段 | 含义 |
|---|---|
| `status` | 界面使用的执行状态。 |
| `at`、`resetAt` | 处理时间、对应的重置时间。 |
| `completed` | 是否取得有效完成确认。 |
| `failureKind` | 固定失败类别，如网络、登录或请求未完成。 |
| `exitCode` | 本机工具退出码；非零表示异常退出。 |
| `timedOut` | 是否达到工具运行时限。 |
| `inputTokens`、`outputTokens` | 输入、输出 Token 计数；Token 是模型处理文本的计数单位。 |
| `quotaObservedAt` | 最近额度读数的时间，用于判断刷新是否取得新数据。 |

无需提供 `secrets.json`、工具登录文件或完整个人数据目录。保留 `window-starter-state.json`，它保存本轮去重依据；反复点击“刷新额度”只会查询额度，不会补发本轮 `hi`。
