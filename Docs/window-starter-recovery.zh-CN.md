# 5 小时 hi 失败后的补发

适用于 0.1.9 正式版；失败恢复功能自 0.1.6-preview.3 起提供，工具路径自动恢复自 0.1.6 起提供。

## 启用和使用

退出旧版 Pulse，解压新版到新文件夹，运行 `Pulse.exe`。在“服务与账号”打开使用本机登录的主 Codex 或 Claude 账号，启用“5 小时重置后发送一次 hi 并刷新额度”。原有开关已启用时会沿用设置。

- Pulse 大约每分钟读取一次额度，不受电脑空闲时普通刷新放慢的影响。
- 5 小时重置时处理一次；新鲜的原始数据报告剩余 100%（已用 0%）时也能触发。本轮成功后不会因为显示仍为 100% 而重复发送。
- 明确的网络连接失败或额度拒绝会保留待处理记录。首次失败后最早 1 分钟重试，再失败等待 2 分钟，随后每次至少等待 5 分钟；只有读到最新可用额度才会发送。周额度不足时继续等待。
- 程序退出、重启后保留待处理记录；离线超过旧版的 5 分钟补发期限也能恢复。
- 发送后重新读取额度；重置时间始终以服务商返回为准。

自动发送遵守“网络与刷新”里的允许开始、结束时间。默认设置为 09:00–18:00；需要全天运行时，把开始与结束时间设为相同。两种触发共享一份记录，每周重置本身不会另发消息。

## 手动补发

账号页新增“再次发送 hi 并刷新额度”。先检查最新额度，再重试当前失败或结果不确定的请求；同一轮已经确认成功时不能重复发送。服务商确认进入新周期后，按钮会再次可用。手动操作不受自动发送时段限制，但仍需启用该账号的开关、本机身份一致且有可用额度。

发送超时、进程中断、部分回复后掉线等情况，服务商可能已经收到请求。因此这些情况不会自动重发；先查看额度和最近请求，再决定是否手动重试。登录或工具路径、模型配置错误也需修好后手动重试。

Codex 升级可能移除旧版本的工具目录。0.1.6 在保存路径失效时会重新查找当前工具；“本机工具完整路径（可选）”通常可留空，避免固定到临时版本目录。找不到任何可用工具时会显示工具缺失；有额度并不代表工具已经启动。有效的自定义路径仍优先使用。

旧版本只记录“已经尝试过”，无法可靠判断请求是否被接收。升级前的失败记录不会盲目自动重放，可以使用新按钮恢复。

## Codex 工具与模型选择（0.1.8）

同一电脑可能同时留有独立命令行安装和桌面应用的新版运行组件。自动 hi 保留有效的手动工具路径；自动查找时，优先使用当前桌面运行组件的有效路径，其次查找最近安装的桌面版本目录，最后使用普通命令行入口。不存在的旧路径会跳过，每次重新查找，不把版本目录写回设置。

账号页的“自动 hi 使用的模型”只控制 Pulse 的自动发送和手动补发，例如填写 `gpt-6.1-terra`，不会修改日常 Codex 聊天模型。点击“应用”、按 Enter 或移开焦点时保存，输入两端空白会去掉；留空删除独立选择，继续跟随 Codex。模型名称以字母或数字开头，只能包含字母、数字、点、下划线和短横线，最多 128 个字符；无效输入不会覆盖已保存值。

发送前仍会只读查询同一 `CODEX_HOME` 和独立工作目录下的 Codex 配置，确认配置可读且使用 OpenAI 提供方。读取配置不会创建对话或发送消息。独立模型设置优先；未填写时读取 Codex 所选模型，再未设置时查询工具报告的可见默认模型。模型通过 `--model` 明确传给隔离的发送命令，不会因为旧的内置模型列表没有它而覆盖用户选择。

没有可用选择、已保存模型名称不合法、配置损坏或使用自定义提供方时停止发送。所选模型被拒绝时也不会自动换回 Astra 或其它模型试发。不会固定推理强度。修改模型设置只影响下一次发送，本身不会发送消息。

状态中的“模型”是本次实际传入的名称。“未发送：无法读取 Codex 模型设置”表示预检未通过；“所选模型不可用”表示请求被拒绝。先确认当前 Codex 能正常发送，选择可用模型，再点击手动重试。额度充足只能说明用量窗口尚有余量，并不保证旧工具兼容当前模型。

## 实现和验证

待处理状态与成功状态分别保存，启动工具前必须先保存记录。保存失败不启动工具；发送后保存结果失败则暂停后续自动发送，并仍尝试刷新额度。定时处理与手动操作共享单次执行锁；刷新期间账号凭据变更会取消本次处理。

自动恢复仅使用与账号匹配、无错误、非过期、非估算的读数；恢复判断有效期为 90 秒，普通重置计划读取有效期为 5 分钟。用原始已用值判断零，不使用界面四舍五入后的百分比。

检查覆盖：网络和额度拒绝、1/2/5 分钟退避、重启恢复、周额度阻止、原始零与新周期防重、手动时段、未确认结果、凭据变更、并发操作，以及发送前后保存失败。所有发送检查使用模拟工具和额度，未向真实账号发送 hi。

初次预览发布时 258 项核心检查全部通过；原生交互、状态保存、布局和动画生命周期回归通过。当前执行会话的 WPF 像素渲染探针也输出全透明，因此像素截图检查未通过视觉验收，功能回归使用显式的 `--skip-raster` 参数；没有把透明图片算作成功截图。本次没有修改悬浮条的外观实现。

## 0.1.9 配置检查与每日上限

账号页新增不会发送消息的配置检查、每日尝试上限及单次和当日 Token 记录。自动与手动共用上限，失败和未确认结果也计次；历史错误与下次发送的配置分开显示。具体说明见[使用与诊断改进](usability-controls.zh-CN.md)。
